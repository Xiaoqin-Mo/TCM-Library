# 药材名录计划 · Herbal Catalog Plan

> 目标：收集中国全部药材，建立结构化药材名录（以《中国药典》为法定基准，
> 向全中药资源扩展），接入现有 TCM-Library 检索体系与后续 RAG。
> 本文件为**计划**；实施前需确认 §7 决策点。

## 1. 目标与范围（三层结构）

| 层 | 范围 | 数量（估算） | 条目深度 | 优先级 |
| --- | --- | --- | --- | --- |
| L0 药典药材 | 《中国药典》2025 版一部收载的**药材和饮片** | 约 620 种（2020 版 616，2025 版微调） | 完整条目（性味归经/功能主治/用法用量/注意/贮藏 + 白话提要） | P0 |
| L1 常用药材 | 药典外临床常用、教材收载品种（含部分民族药习用） | 约 400 种 | 完整条目 | P1 |
| L2 全资源名录 | 第四次全国中药资源普查确认的全部中药资源 | 18817 种（植物 15321 / 菌物 826 / 动物 2517 / 矿物 153） | 名录级条目（药材名/基原/药用部位/分类/分布） | P2（可选，分期推进） |

**说明**：
- 2025 版药典一部中药标准共 3069 种（含中成药、植物油脂和提取物），药材和饮片为其中一类，约 620 种；实际数量以药典目录清点为准（实施第一步即清点确认）。
- L2 全资源以「名录级」收录（可检索、可导航），不做完整药典级条目，避免体量失控。

## 4. 条目规范（L0 完整条目）

### 4.1 frontmatter（含 conditions 扩展）

现有 `conditions` 八个维度 + keywords；药材条目需新增**药性维度**，向后兼容扩展
（schema_version 2 → 2.1，契约允许新增可选字段）：

```yaml
---
id: "yw_mahuang"               # 前缀 yw_ + 药名拼音，全局唯一
book: "中国药典（2025年版）一部"
chapter: "解表药"               # 功效类
section_title: "麻黄"
source_version: "《中华人民共和国药典》2025年版一部"
author: "国家药典委员会"
dynasty: "现代"
type: "yaowu"
conditions:
  zhengxing: ["风寒表实"]
  zhifa: ["发汗解表", "宣肺平喘", "利水消肿"]   # 功能
  bingzheng: ["感冒", "咳喘", "水肿"]          # 主治
  zhengzhuang: ["恶寒发热", "无汗", "咳逆上气"]
  fangming: ["麻黄汤", "麻杏石甘汤"]
  yaoming: ["麻黄"]
  xuewei: []
  jingluo: []
  siqi: ["温"]                  # 【新增】四气：寒/热/温/凉/平
  wuwei: ["辛", "微苦"]         # 【新增】五味
  guijing: ["肺经", "膀胱经"]    # 【新增】归经
  keywords: ["发汗", "解表药", "中国药典"]
weight: 8                      # 药典药材 = 核心梯队
tags: ["中药学", "单味药", "解表药", "中国药典"]
---
```

**扩展步骤**（确认后实施，独立小步）：
1. `schema/frontmatter.schema.json` 增加 `siqi / wuwei / guijing`（数组，open 词表）
2. `schema/controlled_vocabulary.json` 增加四气/五味/十二经词表
3. `scripts/tcm_lib.py` 更新 `MATCH_FIELDS`（3 字段并入检索维度）与 `CATEGORIES`（zhongyao 增 21 功效子类）
4. `manifest.schema.json` 更新 `match_fields`；`docs/rag-contract.md` 标注 schema 2.1（向后兼容）
5. `validate_library.py` / 两个测试同步更新

### 4.2 正文三层

```
**【原文】** 药典要点归纳：来源/基原简述、性味与归经、功能与主治、用法与用量、注意、贮藏
           （归纳表述 + 「据药典 2025 版一部」标注；不整段照搬）
**【古注】** 本草古籍相关条目（公有领域原文，如神农本草经、本草纲目；无则省略）
**【白话提要】** 现代白话：该药是什么、性味功效、主治什么、怎么用、注意什么
```

### 4.3 目录结构

```
library/zhongyao/yaowu/<功效类>/<药名拼音>/
├── yw_<pinyin>.md        # 主条目（药典药材）
└── INDEX.md              # build_index 生成
```

## 5. 收录流程（每味药）

1. **清点**：按药典目录提取药材名单 → 生成清单（`raw/yaodian2025/` 存名单）
2. **建条目**：按模板生成条目（AI 辅助起草 + 人工核校：核对性味归经/功能主治/用法用量/注意）
3. **质量门**：`validate_library.py` + 契约测试 + 回归测试
4. **小步提交**：每批 20–50 条一个 commit（`feat(library): add yaodian herbs batch N`）

## 6. 工作量与节奏

| 阶段 | 内容 | 量 | 人工核校估算 |
| --- | --- | --- | --- |
| A | 药材名录基础设施（分类/字段/模板/词表） | 1 次 | 1–2 天 |
| B | 药典目录清点 + 名单入库 | ~620 条名录 | 1 天 |
| C | 药典药材完整条目（分批，每批 50） | ~620 条 | 12–15 批，AI 起草 + 核校 |
| D | L1 常用药材（药典外） | ~400 条 | 分批 |
| E | L2 全资源名录级（可选） | 18817 条 | 脚本批量生成基础信息 + 抽检 |

**AI 协作模式**：条目由 AI 按模板起草（基于药典要点归纳 + 本草古籍原文），人工（或后续 RAG 管线）核校关键字段；每批核校后合入 dev。

## 7. 决策点（需确认）

1. **范围**：仅 L0 药典（~620）？L0+L1（~1000）？还是含 L2 全资源名录（18817）？
2. **conditions 扩展**：是否同意新增 `siqi / wuwei / guijing` 三个检索维度（schema 2.1，向后兼容）？
3. **收录节奏**：每批 50 条、逐批核校合入，还是按功效类整类推进（每类 20–40 条）？
4. **白话深度**：白话提要为「简明临床向」（每药 3–5 句），还是「详解向」（含用法宜忌、配伍示例）？
5. **基原信息**：药材条目是否含拉丁学名、基原植物、药用部位（药典「来源」项的归纳）？
