# 查询集构造规范（plan-fbr Phase 1）

> 关联：`annotation/guidelines.md`（标注指南，PR #95）· `docs/plan-fbr.md` · Issue #94

## 1. 目的

构造 TCM 中医条文级检索基准的**查询集（query set）**：覆盖三种查询形态，
系统配对"现代↔文言"术语（分面桥评测的基础），支撑 RQ1（语域鸿沟）与 RQ2（分面桥增益）。

## 2. 查询三形态

| 形态 | 定义 | 例 |
|---|---|---|
| `modern` 现代术语 | 现代通行病名/证名/症状名表述 | "感冒"、"糖尿病"、"失眠" |
| `classical` 文言术语 | 古籍原文术语 / 篇章名 / 条文关键词 | "太阳中风"、"消渴"、"百合病" |
| `case` 临床案例式 | 完整自然语言问题，模拟医患提问，常混合两域 | "外感风寒后发热恶寒无汗、身痛，用什么方？" |

## 3. 构造原则

1. **代表性**：覆盖库内 10 大类目录与主要典籍（伤寒/金匮/内经/难经/本草/药典/腧穴/指南/临床/方剂）。
2. **可判定性**：每条查询信息需求明确，标注者可依据指南给出 3/2/1/0 判定。
3. **语域配对**：`modern` 查询尽量携带对应 `classical` 目标（术语对），
   使"现代词 → 分面字段（现代病名/证名）→ 文言正文"这一分面桥路径可评测。
4. **难度分布**：不回避跨语域难例（现代词在原文层必然低命中），难例正是 FBR 的动机来源。
5. **来源可溯**：每条记录来源字段（受控词表 / 篇章名 / 临床常见问题 / 回归种子）。

## 5. 查询记录格式

```json
{
  "qid": "q001",
  "query": "感冒",
  "form": "modern",
  "modern_term": "感冒",
  "classical_term": "太阳中风",
  "source": "受控词表 zhengxing/西医病名",
  "target_books": ["shanghan", "neijing"],
  "notes": ""
}
```

- `modern_term` / `classical_term` 仅 `modern` 与部分 `case` 查询填写（语域配对）；
- `target_books` 为预期覆盖书目（提示性，不参与判定）；
- 相关性判定（3/2/1/0）见 `annotation/guidelines.md`。

## 6. 数量与批次

- 第一批：56 条（现代 18 / 文言 18 / 案例 20），三形态均衡；
- **批次切分**：按候选目标量自适应切分（每批约 350 判定 ≈ 2 小时），共 13 批；
  （即 Issue #94"每批 2 小时左右"的实际落地口径——按判定量而非查询数计）
- **候选池 pooling**：深度 top-20 × 5 检索器 + 语域配对术语扩展（查询与其
  modern/classical 配对词各跑一遍，合并去重），保证"分面桥"两侧相关条目都入池；
  全量约 4800 判定（双标注者各约 13 批 × 2h）。

## 7. 产物

- `queries/query_set_v1.json` —— 查询集 v1（56 条，人工复核后冻结）；
- `data/pool_v1.json` —— 候选池（每查询含 candidates 与检索分数）；
- `gold/annotation_batchN.csv` —— 按批标注 CSV（13 批，列对齐 `annotation/template.csv`）。
