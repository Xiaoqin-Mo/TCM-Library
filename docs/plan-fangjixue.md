## 3. 条目格式硬约束

- 目录：`library/fangji/shifang/<方名拼音>/<方名拼音>_001.md`；目录名 = 方名小写拼音。
- Frontmatter 必填：`id`（与文件名同、全局唯一、`^[a-z0-9_]+$`；先查占用，冲突顺延 `_002`）、
  `book`、`chapter`、`section_title`、`source_version`、`author`、`dynasty`、`type: fangji`、
  `conditions`（12 字段**全为数组**）、`weight`（教材代表方 9）、`tags`。
  - `book: "《方剂学》规划教材（要点归纳）"`；`chapter` = 剂型（如 "解表剂"）；
    `section_title` = 方名+核心功效；`source_version` 注明依据（如「据《方剂学》第九版教材
    与《太平惠民和剂局方》等原书要点归纳」）；`author` 注明原书作者/教材（如 "局方（要点归纳）"）；
    `dynasty` 注明方源年代（如 "宋"）。
- `conditions` 填法：`fangming` 方名；`zhifa` 治法（如 疏散风热/清营解毒）；`bingzheng` 主治病证；
  `zhengzhuang` 主症要点；`yaoming` 组成药物；`zhengxing` 证型（如 风热犯表）；`keywords` 含
  方名、剂型、核心功效、出处；无相关维度置 `[]`。
- 正文三层标记：`**【原文】**` = 方歌 + 组成剂量概要 + 主治要点（教材/原书要点归纳，注明出处）；
  `**【古注】**` = 方解要点（君臣佐使一句，据教材方义归纳）或「本条古注从略」；
  `**【白话提要】**` = 非空：适应证、功效、使用注意（不承诺疗效）。
- 先例：`library/fangji/jingfang/dachengqitang/` 条目（frontmatter 结构、三层标记）。

## 4. 素材与内容纪律

- 依据《方剂学》规划教材与方书原典（《伤寒论》《金匮要略》《太平惠民和剂局方》《丹溪心法》
  《景岳全书》等公有领域古籍）做**要点归纳并标注出处**；禁止整段转载受版权保护教材文本；
  方歌为传统歌诀（公有领域流传），可引但注明「传统方歌」。
- 剂量按教材通行量概要（以「约」「常用量」表述），**不作处方**；条目标注「要点归纳，供参考；
  具体用药请遵医嘱」。无可靠依据的内容不写入。

## 5. 每批收尾清单（集成步骤，由编排者执行）

1. `python3 scripts/build_index.py`
2. `python3 scripts/build_manifest.py`
3. `python3 scripts/export_vocab.py`
4. `python3 scripts/validate_library.py` → 0 错 0 警
5. 同步 `tests/recall_regression.py` 硬编码总数为新总数（2522 → 逐批累加）；新增方若扩充
   既有精确集断言（如方名/治法关键词），按仓库「旧基线子集 + 抽查新增」哲学更新；再跑全绿
6. `python3 tests/test_manifest_contract.py` → 0 错
7. 按 ≤25 条/commit 暂存提交（显式按路径 `git add library/fangji/...`，严禁 `git add -A`）；
   推送分支；`gh pr create --base dev`；验证后合并（`gh pr merge --merge`）。
8. 合并后 `git checkout dev; git pull --ff-only origin dev` 再开始下一批。
